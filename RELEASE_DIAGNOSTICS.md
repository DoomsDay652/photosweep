# Google Play release diagnostics

Release 0.1.2 enables R8 for signed releases. The Android Gradle plugin embeds
its real mapping file in the AAB, so Google Play can decode obfuscated crash
reports automatically. The workflow also saves `mapping.txt` in the
`PhotoSweep-crash-diagnostics` artifact. Keep each mapping with its exact build;
a later build's mapping cannot decode an earlier build's crashes.

The native debug-symbol level is FULL. Available symbols are embedded in the
AAB and the optional `native-debug-symbols.zip` is saved with diagnostics.
`release-diagnostics.txt` reports which native libraries actually have symbols.
Some third-party libraries ship already stripped. Their missing debug information
cannot be regenerated by enabling a build flag; the SDK vendor must supply it.
A native-symbol warning may remain for those libraries. Do not upload placeholder
symbol files or remove a working SDK just to hide the warning.

App class names and development controls are preserved during internal testing.
SDK dependencies use their bundled consumer keep rules. Theme/image resources
are not shrunk. Verify sign-in, deletion, purchase restoration, themes, audio,
photo review and Admin mode on the internal-test build before a production release.

The home-screen footer reads versionName/versionCode from generated BuildConfig,
so every future build automatically displays the correct version and build.
